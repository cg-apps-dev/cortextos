## What it does, mechanically (as-implemented)

- **Runs daemon-side, every 15 minutes** (`HEARTBEAT_STALENESS_INTERVAL_MS`), started by the daemon at boot (`src/daemon/index.ts`). It does not run inside any agent, so an agent hang cannot silence it — that independence is the whole point.
- **Per-agent staleness threshold = the agent's own heartbeat cadence × 2 + 0.5h grace.** Cadence is derived from each agent's *actual* heartbeat cron schedule (read from its `crons.json`), not a fleet-wide constant — so a 4h-cadence agent is flagged at >8.5h stale, and an agent on a different cadence gets its own proportional threshold. This is why the threshold is not a single number you can memorize; it is relative to what each agent's schedule promises.
- **Reads `state/<agent>/heartbeat.json`** (`last_heartbeat` / `timestamp`) from the filesystem — the artifact, not the agent.
- **Excludes stopped/disabled agents** (`enabled-agents.json` `enabled:false` plus other stop signals), so a deliberately-off agent is not a false alarm.
- **Alerts the orchestrator**, with a **60-minute cooldown + dedup** on the alert's content key: an identical alert inside the cooldown window is suppressed, so a persistent staleness does not re-page every 15 minutes. (Collapse-the-flood, the same family as the operational-alert-dedup rule.)

## The three things an alert can mean — read which one you got

1. **Per-agent staleness.** One (or several, but not all) agents past their individual threshold. `ageHours` vs `thresholdHours` are in the alert. This is the ordinary case: that specific agent's heartbeat has lapsed well past twice its own cadence.

2. **Fleet-not-started (a deliberate COLLAPSE, not N alerts).** If **every** running agent is stale at once (≥2 running, none in a blocked state), the watchdog emits **one** `fleet-not-started` alert with the full stale set — NOT one alert per agent. Rationale, and it is load-bearing: all-agents-stale-simultaneously almost never means every agent independently died; it means the *daemon or fleet didn't come up*. Collapsing to one alert both avoids a flood and names the actual likely cause (the shared parent), rather than N misleading "agent X is down" pages. If you get this alert, suspect the daemon/fleet startup, not the individual agents.

3. **BLOCKED (surfaced, never a false pass).** If the watchdog cannot evaluate an agent — **no cadence known** (no readable heartbeat cron), **invalid heartbeat timestamp**, or **no heartbeats scanned at all** — it emits a `blocked` alert for that agent (or `*`) rather than silently treating unknown-as-healthy. A blocked result is a "I could not check this," which is itself worth surfacing: it means the watchdog's own inputs are missing, and unknown must not read as fine. (This is the fail-closed discipline applied to the detector's own preconditions.)

## Responding to an alert

- **Per-agent:** check that agent directly (is its process alive, is it wedged mid-inference, did its cron stop firing). A stale heartbeat past 2× cadence is a real "this agent is not doing its cycle," not noise — the 2×+grace threshold already absorbs one skipped beat.
- **Fleet-not-started:** check the daemon and fleet startup first, before touching individual agents — the collapse is telling you the shared cause is the likely one.
- **Blocked:** fix the watchdog's *input* for that agent (missing/*unparseable* heartbeat cron, corrupt `heartbeat.json`), not the agent's liveness — a blocked alert is about the check, not the agent.

## The limit, stated so it is not over-trusted

**A fresh heartbeat proves the heartbeat mechanism ran, not that the agent's inference is doing useful work.** Much of the fleet's heartbeat string can be watchdog-authored or written early in a cycle, so "not stale" is a lower bar than "healthy." This watchdog closes the *dead-for-hours* gap (which the old >5h-manual-eyeball check missed and which needed an independent daemon-side signal); it does not, and cannot, distinguish idle-but-fine from process-alive-inference-dead within one cadence. That finer distinction remains a separate, still-open problem (see the-analyst's retracted activity-detector work) — do not read a quiet watchdog as proof every agent is productively working, only as proof none has gone stale past twice its promised cadence.
