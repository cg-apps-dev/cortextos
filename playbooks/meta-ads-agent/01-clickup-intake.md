# 01 - ClickUp Intake

Every finished creative that is `📤 ready to post` for Meta gets pulled from ClickUp, classified, and resolved into a write-ready package for the sheet-posting playbook ([02-sheet-posting.md](02-sheet-posting.md)). This playbook covers the ClickUp side: pulling, classifying, flagging, and card lifecycle. Runs autonomously, event-driven: a zero-model launchd watcher (`com.cleangreen.meta-ads.ready-check`, 15 min) wakes the agent only when new ready cards exist, plus the daily 6am PT full sweep (`meta-daily-sweep` cron). The watcher replaced the old 9am/1pm/5pm poll crons - see [fleet/zero-model-monitors.md](../fleet/zero-model-monitors.md).

Derived from: [brain: agents/meta-ads-agent/skills/clickup-intake/SKILL.md](https://github.com/CLEAN-APPS-DEV/clean-green-marketing-brain/blob/main/agents/meta-ads-agent/skills/clickup-intake/SKILL.md) (Stage-1 conventions) + the intake runner ([brain: agents/meta-ads-agent/skills/meta-intake/SKILL.md](https://github.com/CLEAN-APPS-DEV/clean-green-marketing-brain/blob/main/agents/meta-ads-agent/skills/meta-intake/SKILL.md); the executing copy runs from the agent's local, untracked `skills/meta-intake/`). The skill files stay the executable spec - this is the readable sequence.

## Hard rules

1. **Compliance never blocks intake** (Adam, 2026-06-30). Every ad goes on the sheet first; the compliance verdict is a col-B stamp Adam uses to gate posting, never a reason to hold a card off-sheet. The only non-adds are data-integrity: an empty/unparseable creative folder, or an ambiguous product.
2. **Meta only - exclude Axon at two levels.** Card level: Ad Platform=Axon, an AXON name prefix, or the Pod 3 Axon list. Folder level: an Axon-named subfolder or file inside a legitimate Meta card's Drive folder is never picked as the finished folder (Adam, 2026-06-25). **Multiple sibling Finished folders are UNIONED, not single-winner** (fix `327eb7e6`, after 2 live cards silently dropped a non-winning actor's entire video set): when a card's Meta content spans more than one true-sibling `META …-Finished` folder (one per actor), every non-Axon/non-DNU parseable sibling contributes its files - never just one winner. Actor identity is keyed off the per-file `VID_RE` **filename, never the folder name** (folder names get swapped/mislabeled; the filename is authoritative). Cross-folder same-slot collisions are surfaced in a `collisions` list and that variant is **skipped, never silent-first-wins** (intra-folder first-wins is preserved). This is the folder-level face of hard rule 6's "no silent drops."
3. **Classify deterministically, never by eyeballing the card.** The resolver script does a full per-card read and returns product, writer, designer, folder, description by exact custom-field IDs - its output is used verbatim.
4. **Never guess the product.** Ambiguous flower-vs-gummies = flag + skip; wrong-tab rows are a hard error downstream.
5. **Writer + Designer required but non-blocking** (Adam, 2026-06-28). Apply standing conventions first (`MB_CG_IMG_*` -> Writer MB, Designer TS), intake the row regardless, THEN flag the card (marker comment + @leeza + Agent Flagged status) if either is still unset; the daily reconcile sweep backfills the sheet once the team assigns.
6. **No silent drops, no comment spam.** Every non-added card is flagged loudly (comment names the exact reason: EMPTY_FOLDER vs FILES_PRESENT_UNPARSEABLE vs AMBIGUOUS vs MISSING_WRITER_DESIGNER), and flagging is idempotent so repeat wakes never re-spam a stuck card.
7. **One failed card never stops the run.** Log it, continue.
8. **Actor-sheet routing decides WHICH spreadsheet, every card** (Adam, 2026-07-21). Clean Green now runs dedicated Facebook pages tied to specific on-camera actors, each with its own standalone Meta Ads Upload spreadsheet (cloned from the main sheet: `IMAGES` + `VIDEOS` tabs only, no product suffix). Detection is by actor-name match on the card title or creative file naming against the registry - no dedicated ClickUp custom field yet (a future improvement flagged to Adam). No match = the MAIN sheet, still the default and the overwhelming majority of cards. **The registry (current roster + spreadsheet IDs) is read LIVE from [meta-ads-agent skills/clickup-intake/SKILL.md STEP 0](../../agents/meta-ads-agent/skills/clickup-intake/SKILL.md) - it will grow, so never copy the IDs into this or any other playbook.** Everything downstream (copy, compliance scan, mmb batching, launch tracking) targets whichever spreadsheet the card routed to, not always the main one.

## The sequence

1. **Precondition check** (fail-fast): probe Sheets + Drive + ClickUp access. Any failure -> tell the orchestrator, change nothing, stop.
2. **Pull fresh** (never a cached list) from the four ad lists: Static Image Ads, Video Ads, Pod 1 UGC, Pod 2 UGC. Zero ready = log + quiet exit.
3. **Classify each card** via the resolver: product -> tab (Flower vs Sleep Gummies; source list decides IMAGES vs VIDEOS), writer/designer, Drive folder. **Resolve the target spreadsheet here too** (hard rule 8, above): actor match -> that actor's sheet; no match -> the main sheet.
4. **Hand the package to sheet-posting** ([02](02-sheet-posting.md)): the engine plans and writes the rows to the spreadsheet resolved in step 3 (dry-run reviewed first). Images: one row per variant. Videos: one row per finished video across the per-actor finished subfolders - one card can yield ~10 rows.
5. **Verify, then complete the card.** A card only moves to `✅ Posted To Sheet` (status resolved from the card's live list statuses - never a hardcoded string) when 02's verification passes end-to-end: every finished deliverable has a row, every link resolves and is shared, every preview actually rendered. Anything short stays `📤 ready to post` with an exact report of what's missing - a partially-intaked card must never be completed, because that would hide the un-added ads. DONE-WHEN: `skills/meta-intake/intake_completeness_check.py` exits 0 on the new rows (schema-aware image/video, auto-detected from row-1 headers and HALTing loud on neither/both: asserts col-A `=IMAGE(` + thumbnail fetch + the per-schema required cols, and for video that the Ad-Name render CONTAINS the row Variant# - the degenerate-skeleton guard against an all-blank interpolated name. **Exit contract:** 0 = complete (the DONE-WHEN); 1 = a genuine content INCOMPLETE (fix the row + re-run); 2 = HALT - schema-ambiguous OR a degraded/rate-limited read: read it as "could not determine, RETRY," never a content failure, since a degraded read now HALTs exit-2 instead of masquerading as a false exit-1 blank (`gog_get` fails loud on rc!=0, transient-only bounded retry). Added after the 2026-07-09 col-A miss, planted-blank-proven; schema-awareness + fail-loud per `b0c7f183`). Re-touched cards: whether an old card's new files are a re-EDIT (must intake) or a re-EXPORT (dedup, ignore) is decided by the variant-identity + newer-finished-subfolder distinguisher - authoritative in the clickup-intake SKILL Step 5 (the meta-intake SKILL's Card-ID rule cross-references it) + the error-class registry ([fleet/standing-rules.md](../fleet/standing-rules.md)); the ambiguous middle is flagged for a human, row disposition only (a compliance verdict never waits on it).
6. **Copy + scan follow immediately**: ad copy ([03](03-ad-copy.md)) runs on the new rows, then the compliance scan ([08](08-compliance-scan.md)) stamps col B. A fresh row is never left copy-less or verdict-less.
7. **Report to the orchestrator**: cards intaken/completed/flagged with reasons. Proactive reports go to the orchestrator only; Adam's direct pings get brief operational answers with the orchestrator notified.
